# Koebuta v1.00 — 編集の安定化と分割・結合の確認

> 旧v1の履歴資料です。正式版の起動と操作は [Notebook v2操作ガイド](NOTEBOOK_V2_GUIDE.md) を参照してください。

v1.4通しレビューの再現不具合R1–R9を修正し、自動分割・結合を利用者が確認して仕上げる方式へ更新したリリース候補です。2026-11-01作成。Colab GPUとブラウザー実操作は未検証です。

## 変更

- 表示元ページと保存先を結び付け、表示開始行の入力だけで別行を上書きしない。古い状態の表保存・未登録話者参照を拒否する。
- 話者変更・Undo・編集後は表、話者フォーム、概要、確認事項、過去の音声出力を同期する。
- Undoは台本・声の割り当て・試作の対応をまとめて最大10操作復元。参照WAVと試作WAVのファイル名を一意にして上書きを避ける。
- 入力エラーで表を戻さず、未保存の入力を保持。長さスライダーも本文等を消さない。
- ルビの親文字と読みを含む範囲を保護し、分割前後の読みの連結一致を確認。書記素単位で絵文字や結合文字を保護。
- 自動分割は目標付近の段落・文末・改行・読点・余韻記号等を優先。候補がなければ文字数付近で分割し、自然な区切りがなかったことを明示する。文法解析は使用しない。
- 全ての分割・結合の結果に要確認印を残す。確認済み操作とUndoに対応。印は任意拡張 `koebuta_edit` でJSONへ保存し、再読み込みでも保持する。
- 話者・感情・演技等の互換性、原稿との隣接、明示的な間の条件は自動結合で維持する。原文と異なる読み上げ文は対応位置を推測しないため手動調整が必要。
- 操作と生成を共通キューへ直列化。生成中に作品状態が変わった場合も古い成果を登録しない。ランタイム初期化をロックする。
- 話者の声の特徴へ普段の話し方が保存ごとに累積する問題、本文のない区切りが前方にあると結合できない問題、先頭区切りの間が最初の発話後へ移動する問題を修正。
- キャッシュキーへモデル・codec revision・取得した上流commitを追加。参照音声ZIPへ話者対応manifestを追加。
- Gradioを6.5.1に固定し、書記素処理用regexを追加。上流mainの既定取得は継続し、未検証のcommitを検証済みとして固定しない。
- 原文照合の限界、任意fixture欠落時のSKIP表示、説明書を更新。CLI・HTML版は追加していない。

## 残る確認

Colab GPUでのセットアップ、モデル・codec読込、試作・単一発話・全体生成、キャッシュ再利用と実際の朗読品質。ブラウザーでのセル編集、保存失敗時の入力保持、話者変更・Undo、待機中の操作と表示を確認する。静的検査・モック・Gradio API試験はこれらを代替しない。

文字数は目安であり、分割後の自然さやモデル入力上限を保証しない。ルビ等の保護によって長文が残る場合も警告を維持する。確認済みは利用者が内容を確認した印で、音声品質の保証ではない。変更行だけの絞り込み、Redo、オフラインHTML版は未実装。元原稿の欠落・重複の完全照合も未実装。

今回の作業環境にはGit接続先がなく、コミット・プッシュは行っていない。


## 2026-11-02 一括調整の修正

候補確認時に表を保存・整形した後、古い表示を変更扱いして適用承認を無効化する問題を修正。感情IDと表示名、間の整数表現を正規化して比較し、候補確認後は表も同期する。内容が変わらない保存は履歴・作品状態を進めない。

任意項目sourceがない場合も、同一話者・感情等の条件を満たす隣接発話は文字を追加せず結合する。sourceがある場合の原稿照合は維持する。候補欄には短文の結合見送り理由も表示する。読み上げ文・ルビ等の既存の自動結合制約は残る。

python test_batch_fix.py で既存回帰試験と追加3条件が通過。実作品fixtureは未同梱のためSKIP。Colab GPU・ブラウザー実操作は未実施。


## 警告を無視する強制分割・結合（2026-11-02）

長さ調整欄の「警告を無視して強制分割・結合する」は初期状態オフ。有効にすると候補を再計算し、適用確認チェックを解除します。適用には改めて確認チェックを入れてください。

原文照合、ルビ・読み上げ文との対応、話者・感情・演技の違い、明示的な間などの保全条件を省略します。原文と読みの対応が壊れる可能性を許容する処理です。長文は文字数に従い分割し、読みの位置は原文中の位置に比例させて推定します。短文結合では前の行の話者・感情・演技、後ろの行の間を採用します。原稿中の位置が確認できない場合は間の文字を推測補完せず隣接する本文を結合します。

文字数の目安に基づいて処理しますが、結合後の文字数が上限内に収まることは保証しません。区切り行と空本文は結合しません。変更行には「強制処理・原文と読みの対応を確認」の印が付きます。必ず手直し・試聴し、必要ならUndoしてください。元原稿sourceそのものは書き換えません。

非GPU試験 `python test_force_length.py` は既存試験も含めて通過。ブラウザー実操作・GPU試聴は未実施。


## 再レビュー5件の修正（2026-11-02）

強制モードも目標文字数付近の段落・文末・改行・読点等を優先し、候補がない場合に文字数付近へフォールバックする。強制モードの候補に通常モードの見送り理由を混ぜない。

文字数スライダーを変更すると、入力中の表を検証・保存してから、ルビ形式を含む同じ台本から表と候補を再計算する。入力エラーの場合は表を保持して候補の更新を中止し、エラーを表示する。原文のルビ記法を文字数へ混ぜない。強制処理・フォールバックの印は後続の分割・結合へ引き継ぐ（結合後半の履歴も含む）。

試験は `python test_review_fixes.py`。既存試験を含み、自然な句点位置での強制分割、候補と見送り理由の整合、ルビの読み文字数、未保存本文と候補の同期、強制処理履歴とUndoを検査する。Colab GPUとブラウザー実操作は別途確認が必要。


## v1.00 ルビ説明と最終追加試験

手動結合でルビの対象が結合境界をまたいで広がる場合、各行の読みを `tts_text` に保持する。例：`東` と `京《きょう》` の結合は、原文を `東京《きょう》`、読みを `東きょう` として保持する。

非GPU回帰試験の全体は `python test_merge_reading.py` で実行する。この入口から `test_review_fixes.py` → `test_force_length.py` → `test_batch_fix.py` → `test_koebuta_stability_v1.00.py` → `test_koebuta_without_gpu_v1.00.py` を順に呼び出す。実作品fixtureがない試験はSKIP。実GPU・ブラウザー操作・音質の確認は別途必要。

入力元と `text_format` を指定し、曖昧な括弧の意図はLLMと利用者が確認する。原文の記法を統一せず、必要な発話の完成した `tts_text` に読みを指定する。なろうの丸括弧を意味に従って判別する機能をKoebutaへ追加したものではない。具体的な依頼方法は `02_CHAT_PROMPT.md`・`03C_READING_ADDON.md`、対応範囲は `USER_GUIDE_FAQ.md` を参照。
