# 03A 長編シナリオ化追加指示 v0.3

[02の共通手順](02_CHAT_PROMPT.md)では一度に処理できない長編に追加します。JSONの構造は[01](01_SPEC_SHEET.md)、演出設計の順序は02に従います。

## 追加する指示

```text
【全体把握と演出の引き継ぎ】
可能なら作品全体を先に通読してください。全文を扱えない場合は、実際に提供された目次・あらすじ・章の要約・処理済み範囲から暫定的な全体像と演出方針を立てます。未読部分を理解済みとして扱いません。
章・場面など意味のある処理範囲を定め、全体方針と前後の文脈を確認し、担当場面の演出を設計してから発話へ分割します。20〜80文字の推奨範囲と短文の注意は02に従い、原文・話者・意味・演出の境界を優先します。

制作メモへ次を引き継いでください。
- 朗読形式、話者IDと人物の対応、声の情報・普段の話し方
- 作品全体の演出方針、章・場面の構成、主要な転換点
- 各場面の演出状態、前後へ続く感情・緊張・雰囲気
- 読み方針（既定B）と確定した語の読み、ユーザーの演出指定
- 見出し類の改変許可の有無・対象範囲・変更前後・対象発話ID（読み方針Cの許可とは別）
- 完了した原稿範囲、次の範囲、未読範囲、未確定事項
- 新たな作品情報、演出・解釈を修正した理由と影響範囲

各回のJSONには担当範囲だけを欠落なく含め、参考用の前後文章を再出力しません。同一人物のIDは作品全体で一貫させ、一人朗読では全編一つの話者IDです。発話IDにはc02_t015などの接頭辞を用い、作品内で重複させません。
後から解釈や演出の修正が必要になった場合は、影響する場面・発話IDを明示し、ユーザーの確定事項を無断で覆さず必要な範囲だけ直します。
制作メモは原稿の代わりではありません。必要な前後文脈を参照し、正式なシナリオJSONへ独自キーとして追加しません。

【出力・検証】
各回は担当範囲の完全なJSONを出力します。制作メモ・質問・完了／未処理範囲は別の応答またはファイルへ分けます。
複数JSONの統合は利用者または依頼された外部ツールが行います。統合時は話者と発話ID、原稿範囲の重複・欠落、順序、演出の連続性を確認し、未実施の検査は未実施と記録します。
sourceを含める場合は、そのJSONへ入力した担当範囲の元原稿を保持し、参考文脈を混ぜません。作品全体の原稿を一部範囲のJSONへ含める場合は、照合対象範囲が異なることを制作メモに明示します。
章頭などの短い見出しを結合する場合も02に従い、連続する原稿範囲の文字・空白・改行・順序を保ちます。改変許可なしに紹介文へ置き換えません。
出力が途中で切れたら完成品として扱わず、完了・未処理範囲を示して継続方法を調整してください。
```

ファイル操作可能な場合は演出計画と引き継ぎメモを別ファイルに保存できます。原稿や正式JSONを重複保存する新しい必須フィールドは設けません。
