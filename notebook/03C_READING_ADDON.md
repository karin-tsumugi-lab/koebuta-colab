# 読み上げ文の追加調整（任意モジュール）

**いつ使うか：** 青空文庫などの古典的な表記、難読漢字、作者独自のルビ・当て字が多い作品で、通常のシナリオ化の後に読みを調整したいときだけ使います。一般的な現代文には追加不要です。ただし、なろう由来の丸括弧など、ルビと補足の区別が必要な発話にも利用できます。

**使い方：** まず `02_CHAT_PROMPT.md` でシナリオJSONを作り、この指示は必要な発話だけに適用します。作品全体を再生成する必要はありません。原稿の `text`、話者ID、発話ID、順番は変更しません。

## LLMへ追加する依頼文

```text
あなたは朗読用シナリオの読み上げ文を調整します。
これは通常の台本編集とは別の作業です。原文 text、話者、発話ID、発話順は変えないでください。

まず、読み上げ方針について次の3つから利用者に選んでもらってください。
A. 原文優先：原稿にある明示ルビだけを読みへ反映する。難読字の大幅な調整はしない。
B. 読み補助：明示ルビに加え、読み間違えやすい漢字や固有名詞を必要な発話だけ補助する。
C. 表記の平易化：Bに加え、読みに影響しない範囲で古い表記や難しい漢字を読み上げ文だけ一般的な表記にする。

入力元のサイト・ルビ形式を確認します。すでに共有されている方針は再質問しません。
丸括弧の内容は、文脈に従ってルビか補足・台詞等かを判断してください。かなだけの括弧を一律にルビ扱いせず、判断できない箇所は発話ID・原文・候補を示して確認します。補足を読むか省くかも、未確定なら相談します。LLMの判断にも誤りがあるため、曖昧なものを確定したように扱いません。
text と source のルビ記法は変換しません。必要な発話の tts_text に完成した読みを指定します。tts_text は再度ルビ変換されないため、その発話のすべてのルビを読みへ展開し、他の本文・句読点も含めてください。補足は確認した方針に従い、ルビと一緒に機械的に消さないでください。
確信できない読み、作者独自の読み、作品の鍵になる語は必要なものだけ候補を提示して相談してください。
表記を直す場合、内容の要約、意味の変化、作者指定の読みの上書きは避けてください。

方針が確定したら、対象発話の id と、発話全文の tts_text を提示してください。
発話の一部分だけでなく、読み上げる文章全体を tts_text に入れてください。
直す必要がない発話は省略してください。JSON構文・原文一致やハッシュなど、機械的な検証結果の自己申告は不要です。
```

## 返答の例

```json
{
  "reading_updates": [
    {"id": "t003", "tts_text": "桜の樹の下にはしたいが埋まっている！"}
  ]
}
```

ここでの `reading_updates` は**追加調整結果を人間が確認するための補助形式**であり、シナリオJSON本体のキーではありません。確認後、対象発話の `tts_text` に内容を反映してください。外部ツールやエージェントで反映する場合も、必ず対象IDの存在を検証し、原文 `text` は変更しないでください。
