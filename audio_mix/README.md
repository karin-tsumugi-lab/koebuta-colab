# Yomibuta 効果音・環境音ミキシングガイド

Yomibuta で生成した朗読音声（`result.wav` / `segments.zip`、既定 **44.1 kHz**）に、外部の効果音（SE）や環境音（Ambience）を自然に組み合わせるための音量基準とミキシング手順です。

シナリオJSONの `notes` に書き留めた `[効果音]`・`[編集]` の指示をもとに、DAWや同梱の自動合成補助スクリプト（`audio_mix/yomibuta_mix.py`）で仕上げる際の指針として使います。

---

## 1. なぜ「単純なピークノーマライズ」では破綻するのか

市販・配布の効果音素材集をそのままTTS音声と混ぜたり、すべての素材を同じピーク値（例：`-1 dB` や `-3 dB`）にノーマライズしたりすると、次の理由で不自然になります。

1. **音の「現実の大小」が壊れる**:\
   衣擦れのような極小音（Peak `-40 〜 -50 dBFS`）とドアの開閉音（Peak `-10 dBFS`）を同じピーク値に揃えると、服が擦れる音がドアを叩きつける音と同じ爆音になり、さらにマイクのホワイトノイズ（サーッという底ノイズ）まで大きく持ち上がってしまいます。
2. **瞬間ピークと実感音量の差（クレスト比）**:\
   ノック音や足音のような衝撃音は一瞬だけピークが高く、シャワーや雨音のような定常音はピークと実感音量が近い構造です。ピーク基準で揃えると、衝撃音は小さく聴こえ、定常音はうるさく聴こえます。
3. **TTS音声側にヘッドルームがない**:\
   Drama-3（未正規化時）や Irodori-TTS の生成音声は、発話によってはピークが高くアクティブRMS `-13 〜 -15 dBFS` 前後になることがあります。そのまま環境音を加算合成すると 0 dBFS を超えて音割れ（クリップ）します。
4. **フォーマット・チャンネルの混在**:\
   Drama-3出力は `44.1kHz / 1ch（モノラル）/ 16bit` ですが、効果音素材には `24bit PCM`、`32bit float`、さらにステレオ／バイノーラル（2ch）が混在しています。

## 2. ミキシングの基準（TTSの声を基準 `0 dB` とする相対設計）

**ピーク値ではなく、鳴っている区間の実効音量（アクティブRMS / Short-term LUFS）** を基準に、次の手順で音量バランスを組み立てます。

### 土台（マスターとTTS音声）
- **出力フォーマットを `44.1kHz / 2ch ステレオ` に統一する**（ジョブ設定の `sampleRate` に自動追従）\
  モノラルのTTS音声は左右均等（センター）に配置します。これにより、ステレオ・バイノーラル収録の効果音をモノラル化による位相劣化なしでそのまま活かせます。
- **TTS音声にヘッドルームを確保する**\
  合成前にTTS音声の発話アクティブRMSを **`-18 dBFS`** 前後（目安として元音声から `-3 〜 -4 dB` 程度下げる）に整えます。

### 役割別（4カテゴリ）の音量ターゲット

TTSの発話アクティブRMS（`-18 dBFS`）を基準 `0 dB` とした推奨値です。

| カテゴリ（スクリプト指定名） | 配置・用途 | 具体例 | 声に対する相対音量 | 絶対目安（TTS=-18dB時） | 注意点・処理 |
|---|---|---|---:|---:|---|
| **① 強調・動作SE**（`action`） | **発話の間**に挟む（注目させたい動作・場面転換） | ノック、ドア開閉、物を置く、椅子を引く、チャック | **-6 〜 -10 dB**（既定 `-8 dB`） | **-24 〜 -28 dBFS** | 瞬間ピーク上限は `-6 dBFS` 程度。声より大きくしない。 |
| **② 微細フォリーSE**（`foley`） | **発話の間・直前**に挟む（繊細な生活音） | 衣擦れ、布・布団の音、スリッパ・裸足の足音、紙をめくる | **-14 〜 -20 dB**（既定 `-16 dB`） | **-32 〜 -38 dBFS** | **声と同じ音量に持ち上げない。** 極小音素材は **最大ブースト上限（`+24 dB` 目安）** を設けて底ノイズの浮き上がりを防ぐ。 |
| **③ 連続・環境音**（`ambience`） | **発話の裏**に同時合成する背景音 | 雨音、シャワー、室内空調、カフェ・教室の環境音、焚き火 | **-20 〜 -26 dB**（既定 `-22 dB`） | **-38 〜 -44 dBFS** | 発話中はさらに **`-3 〜 -5 dB` ダッキング**（自動で少し下げる）すると声が明瞭になる。前後 **0.5〜1.5秒フェード** 必須。 |
| **④ 壁越し・遠景音**（`distant`） | **発話の裏**にうっすら敷く遠い音 | ドア越しの水音、遠くの足音、窓外の街騒音 | **-26 〜 -32 dB**（既定 `-28 dB`） | **-44 〜 -50 dBFS** | 上げすぎると声の帯域と被ってこもるため、存在を感じる最小限に留める。 |

## 3. 自然に聴かせるための4つの実践ルール

1. **ハイパスフィルタ（HPF `80〜100 Hz`）**:\
   生録りの効果音・環境音には空調や床の振動などの超低音ノイズが含まれがちです。SE・環境音トラックに軽くローカットをかけると、クリアなTTS音声にスッと馴染みます。
2. **最大ブースト上限（Max Gain Cap: `+24 dB`）**:\
   録音レベルが極端に小さい素材（例：`-50 dBFS`）を自動音量合わせすると、ノイズフロアまで持ち上がります。自動ゲインには必ず上限を設けます。
3. **発話の間にSEを挟むときの呼吸（前後マージン）**:\
   発話の直後 `0 ms` でSEが鳴り始めると機械的になります。\
   **発話終了 → `150〜300 ms` → SE再生（前後 `30〜50 ms` フェード）→ `200〜400 ms` → 次の発話** を基本にすると自然な呼吸になります。
4. **最終段のリミッター（`-1.0 dBFS`）**:\
   すべてのトラックを加算合成したマスターの最終段で、`-1.0 dBFS` 付近のソフトリミッターを通してデジタルクリップを防ぎます。

## 4. 自動合成補助スクリプト（`audio_mix/yomibuta_mix.py`）の使い方

標準Python（3.10以上、外部ライブラリ不要）で動作し、16bit/24bit/32bit PCM および 32bit float のWAV素材をそのまま読み込んで、上記の基準で自動ミキシングできる補助スクリプトを同梱しています。

### 手順1：素材の音量を確認する（任意）

```bash
python3 audio_mix/yomibuta_mix.py --inspect sfx/door.wav sfx/cloth.wav sfx/rain.wav
```

各WAVの形式（Hz / ch / bit）、Peak、アクティブRMS、4カテゴリそれぞれの推奨ゲイン（dB）が表示されます。

### 手順2：CLI生成結果からミキシング計画のひな形（`mix_plan.json`）を作る

Yomibuta CLI の出力フォルダー（`works/my_book/run01`）には `plan.json` と `segments.zip` が必要です。このフォルダーとシナリオJSONを渡すと、発話順・`pause_after_ms`・`notes` メモを転記した `mix_plan.json` のひな形が生成されます。

```bash
python3 audio_mix/yomibuta_mix.py \
  --init-plan works/my_book/mix_plan.json \
  --run-dir works/my_book/run01 \
  --scenario works/my_book/scenario.json
```

### 手順3：`mix_plan.json` に効果音・環境音を書き足す

生成された `mix_plan.json` の `notes` を参考に、発話の間に挟むSE（`insert_after`）や、裏に敷く環境音（`overlays`）を追記します。

```json
{
  "target_tts_rms_db": -18.0,
  "sample_rate": 44100,
  "segments_zip": "run01/segments.zip",
  "utterances": [
    {
      "id": "t0010",
      "file": "audio/t0010_xxxx.wav",
      "pause_after_ms": 280,
      "notes": ["[効果音] この発話の直後にドアをノックする音"],
      "insert_after": [
        {
          "wav": "sfx/knock.wav",
          "category": "action",
          "pre_gap_ms": 200,
          "post_gap_ms": 300,
          "fade_in_ms": 30,
          "fade_out_ms": 50
        }
      ]
    },
    {
      "id": "t0020",
      "file": "audio/t0020_yyyy.wav",
      "pause_after_ms": 280
    }
  ],
  "overlays": [
    {
      "wav": "sfx/rain_loop.wav",
      "category": "ambience",
      "start_id": "t0010",
      "end_id": "t0020",
      "loop": true,
      "duck_db": -4.0,
      "fade_in_ms": 800,
      "fade_out_ms": 1200
    }
  ]
}
```

- `category` は `"action"` / `"foley"` / `"ambience"` / `"distant"` から選びます（さらに微調整したい場合は `"gain_offset_db": -2.0` のように相対補正を足せます）。
- 長い素材の一部分だけ使いたい場合は `"trim_start_ms": 1000, "trim_end_ms": 3500` を指定できます。
- `insert_after` に効果音を指定した発話では、既存の `pause_after_ms` を効果音とその前後の間で置き換えます。間の長さは `pre_gap_ms` と `post_gap_ms` で調整してください。

### 手順4：`--dry-run` で確認し、ミキシング済みWAVを書き出す

```bash
# 事前確認（各素材の測定RMS・適用ゲイン・総再生時間を表示）
python3 audio_mix/yomibuta_mix.py --plan works/my_book/mix_plan.json --dry-run

# ステレオWAVへ自動合成して書き出し
python3 audio_mix/yomibuta_mix.py \
  --plan works/my_book/mix_plan.json \
  --out works/my_book/result_mixed.wav
```

`--out` には新しいファイル名を指定してください。すでに存在するWAVは保護されます。試し直す場合は `result_mixed_02.wav` などの別名を使います。`--overwrite` は計画JSONの作成時にだけ使えます。

### 長編は章ごとに書き出す

現在のスクリプトは、読み込んだ全発話・効果音データ（モノラルのステレオ展開配列を含む）とマスター合成用 float32 ステレオバッファ、最終出力の 16bit PCM 配列をメモリ上に保持します。44.1 kHz ステレオの場合、マスター合成用バッファ単体で約 1.3 GB／時間ですが、読み込み済み発話や変換用一時バッファを含めた**実ピークメモリは 1時間あたり約 3.1 GB 超**に達します。長編では章ごとの CLI 出力からそれぞれミキシング計画を作り、章別 WAV を書き出してください。全編を 1 本にする場合は、書き出した章別 WAV を音声編集ソフト等で順に結合し、章をまたぐ環境音はその結合時に調整してください。
