# Notebook v2 原文不一致の警告化・レビュー

2026-11-16（日本時間）。シナリオ化プロンプトv0.3の文書改訂後、原文不一致による停止を外し、ほかの検査を維持する追加依頼を受けて修正した。JSON交換形式はv1のまま。

## 修正結果

- 正式Notebook v2は、`source`に発話の`text`を順序どおり発見できない場合、対象発話の「警告」を返す。警告だけなら作品読み込み・生成計画へ進める。
- 許可済み見出し改変か意図しない本文差分かを確認する文を、読み込み結果と生成計画確認へ表示する。これは許可の自動認識・承認ではなく、本文の不一致も同じ警告になる。
- `source`や`text`は書き換えず、元の照合も残す。既存同様、最初の不一致だけを指摘する順序付き部分照合であり、全文の完全性証明ではない。
- 話者・発話ID、空の本文、TTS片の不整合、不正な設定・参照パス・項目種別などの停止条件は維持する。
- v1を読み込むビルダーでv2専用の差分を適用し、正式Notebookを再生成する。旧v1と旧プロトタイプの内容・挙動は変更しない。通常のビルドも正式版だけを書き出す。
- README、01・02・03B、エージェント手順、エディタ案内、操作ガイドなどから修正前の「Notebookでは見出しを改変できない」という制約を除き、警告の運用へ統一した。
- GitHub Actionsの対象パスと実行コマンドへ、v2の検証・再現ビルド試験を追加した。

## 修正後レビュー

- 停止判定は`警告`だけを除外する。今回この区分へ変更したのは原文照合の不一致だけで、ほかの`要確認`・`エラー`を包括的に許可していない。
- `build_plan`で原文警告を計画の警告一覧へ加え、既存の短文・TTS片の警告も維持する。読み込み時にも一覧を表示し、処理成功だけを返して不一致を隠す経路を避けた。
- 旧v1のコピーを直接編集せず、v2生成時に限定して変更。置換元が一意でなくなった場合はビルドを失敗させ、上流変更に黙って追従しない。
- 正式Notebookの変更セルは操作案内・検証・計画・埋め込みUIの4セルだけ。全コードセルの構文と、実行出力・実行番号がクリアされていることも確認した。
- メイン担当の差分・仕様レビューと、テスト担当による30件の実行・表示経路の確認を実施。この範囲で修正の統合を推奨する。mainへのマージは未実施。
