# CLI忠実生成 実装・検証記録

2026-11-16。実装基準は [仕様v0.2](CLI_FAITHFUL_SPEC.md)。作業ブランチ `codex/cli-faithful-v02`、基点 `9166f81892b725359a6f8368fdab3b70479a7b95`。シナリオ化プロンプト改訂PR #7を基点とし、その変更を混ぜずに別PRでレビューする。mainへの統合は未実施。

## 実装した範囲

- 新入口 `irodori_generate.py` に専用の検査・決定的計画 `faithful.py` と実行契約 `koebuta-faithful-v1` を追加。ホストから遠隔まで同じ計画を再構築して照合する。旧normalize/prepare/worker経路を通さない。
- 発話を自動分割・結合・補完せず、任意sourceを生成しない。明示ルビと感情・演技タグだけを生成要求へ適用する。入力シナリオを別記録のscenarioへ保持し、書き戻さない。
- 明示TTS片と親ID／片番号の対応、`--ids`、選択範囲だけの参照音声検査・転送、親全片完成時の親WAVを実装。
- 明示休止の0・優先順位・最大値・冒頭末尾・片間0・疎な選択の規則を実装。改行・空行数から休止を作らない。
- 構造診断、長さの段階別通知、設定による演出抑制、順序付き原文照合警告を計画へ保存。新入口の未指定acting/emotion/narratorEmotionはtrue。
- 既存のTTS仮想環境・resident・透かし・固定モデル版・輸送・回収・停止を利用する。residentの実行契約を分離し、遠隔でも旧自動分割へ戻らない。既存job.jsonがあるジョブIDは拒否し、既存成果物を再利用・上書きしない。
- 新しい実行契約は転送記録であり、交換形式v1のフィールド変更ではない。generated_project.jsonは実行記録で、HTMLへ渡すシナリオ単体ではない。

## 要件と観測を対応させた確認

| 要件 | 観測・根拠 |
| --- | --- |
| 文・明示片をそのまま生成 | 改行付き見出しと80文字超でも要求数・本文が入力どおり。模擬遠隔実行では旧分割器を呼ぶと失敗するモックを置き、非呼出しを確認 |
| 明示片の整合性 | 連結不一致、空片、2片未満、結合濁点・ZWJ・国旗・Hangul・CRLF途中等を拒否。感情と演技Captionは各片へ継承 |
| 再生成の対象 | 親と片を混在指定して入力順・重複除去。空・不存在・区切りIDは失敗。一片選択はselectionで親完成一覧・親WAVに入らない |
| 休止 | 0優先・区切り最大値・共通値・競合診断・明示の両端・片間0・疎選択を計画で確認。実PCMの結合は100フレーム×3片＋200/900/300ms＝1700フレーム、親WAVは200フレーム |
| 元入力とsource | 元オブジェクト・入力ファイルを保持、source未提供なら追加なし。不一致は警告、照合差分だけで生成を止めない。転送後のsource差し替えも計画署名不一致としてモデルロード前に拒否 |
| ホスト／遠隔の一致 | 同じ参照WAVが別パスでも署名一致、音声内容変更は不一致。遠隔はモデル取得前に署名を検査。回収した契約・範囲・元入力・音声ID順・親WAVを再検査 |
| 部分失敗を成功にしない | WAV欠損・破損・不完全生成は従来どおり失敗。親WAV結合失敗もmanifestをfailedにする。停止だけの失敗は回収音声の成功と分ける |
| 新旧の分離 | 旧分割関数・旧worker/CLI入口は維持。共有jobsの追加引数は任意で、旧呼出しは既存assembly経路を使う。既存CLI30件とNotebook30件・HTML絵文字検査が成功 |

## 未実施・制限

初回コミット時点では実Colab輸送、新経路の実GPU生成・resident実機起動、音声試聴、長編性能は未実施だった。下記のMuse実機試験と利用者の試聴報告で小規模生成を追認した。長編性能・長時間セッションの継続性・透かしの独立デコードは引き続き未実施。

候補採用・既存全編への差し替え・旧キャッシュ移植は対象外。CLIの実行契約を理解しない外部の独自改変は別途確認が必要。Notebook・HTML・Fastの本体は変更していない。入力は各JSONと実行記録込みの転送JSONが2MiB以内である必要があり、転送上限もホストで事前検査する。
