# シナリオ化プロンプトの固定レビューケース

v0.3以降の文書改訂と外部LLM比較に使う共通入力です。原稿と条件を固定し、演出や分割位置の完全一致は求めません。実際のLLM出力・音声生成を行っていなければ、机上評価と記録してください。

## 共通原稿

レビュー用の創作で、実在作品の引用ではありません。

```text
春の灯
架空花子
第一章
雨はやんでいた。千代は窓を開け、濡れた庭を見渡した。
「もう行くの？」
振り返った兄は笑おうとしたが、その口元はすぐに曇った。
「うん。日が暮れる前には戻るよ」
千代はうなずいた。けれど、戸が閉まるまで指先を窓枠から離せなかった。
```

## 条件と確認点

| ケース | 条件 | 確認する結果 |
| --- | --- | --- |
| 1 | 一人朗読、読みB、見出し改変不許可 | 話者一人・全発話同じID。見出しの文字・改行・順序を保持し、水増ししない。自然なら見出しや地の文・台詞の結合も可能で、全行を必ず単独発話にする必要はない |
| 2 | 複数人朗読、読みB、見出し改変不許可 | 地の文は `name: "地の文"`・`kind: "narrator"`。人物は千代・兄を文脈から区別し、呼びかけられた相手を話者としない。異なる話者を一発話へ結合しない |
| 3 | 一人朗読、読みB、タイトル・著者名・章題の必要最小限の改変を明示許可 | 許可範囲内で朗読導入を作れる。本文・台詞は保持し、作品名・著者・章番号を創作しない。許可と変更前後の対応はJSON外へ記録する |
| 4 | 一人朗読、読みCの表記平易化を明示許可、見出しのtext改変は不許可 | Cを見出し改変許可と取り違えない。必要な発話のtts_textだけを調整し、不要なら調整しない。読みだけの修正でID・順序・演出を変えない |
| 5 | 長編の途中部分だけを提供し、既存メモを引き継ぐ | 未読の前後を理解済みとしない。担当範囲のみを出力し、既存ID・声・演出・読み・許可を継承。参考文脈を重複出力しない |

ケース5では、担当範囲を「この抜粋の末尾」、既存話者IDを `reader`（一人朗読）、最後の発話IDを `c01_t020`、読みB・見出し改変不許可、全体方針を「作品の心理の揺れを抑制的に表す」、直前の場面を「兄が『うん。日が暮れる前には戻るよ』と答えたところ」と指定します。上の原稿から「千代はうなずいた。」以降だけを新しい担当原稿とし、その前は既読の参考文脈として渡します。未提供の続きや人物設定を創作しません。

見出しを原文不変で結合した場合の `text` の例です。JSON中の `\n` は実際の改行を表します。

```json
{"text":"春の灯\n架空花子\n第一章"}
```

これは部分例であり、そのまま読み込む完全なシナリオJSONではありません。結合を義務付けず、TTSが安定する保証もしません。現行CLIはこの改行付き見出しを3つの短い生成片へ分けるため、原文不変の結合と短文生成の回避は区別して評価します。

## 追加の境界ケース

- **許可範囲の外縁：** 原稿に目次・奥付・刊行情報・ページの柱・定型前後文があっても、タイトル等の改変許可を自動拡張せず、無断で削除しない。
- **区切り：** 原稿に `＊＊＊` がある場合、交換形式では `speaker_id` 省略可、現行CLI向けでは登録済みIDと原稿どおりの `text` を付ける。`pause_after_ms` を区切りにも指定できる。
- **空行だけの区切り：** CLIの空text拒否を避けるために記号を創作しない。区切り項目を作らず直前の発話の `pause_after_ms` を使える。元原稿を含めるなら空行も `source` に保持する。
- **感情の反映：** 語り手のemotionを付けたJSONと、CLIの `emotion`・`narratorEmotion` の設定を分けて確認する。シナリオの必須項目へ生成設定を混ぜない。
- **位置指定：** 読みの追加調整でも `tts_text` 内の既存の位置指定絵文字を失わず、発話全文を保持する。感情併用を未検証のまま一律禁止しない。

## 比較の記録方法

使用したプロンプトのコミット・LLM・実行日、条件、追加質問、JSON構文とID、原稿の欠落・重複・許可範囲、読みと位置タグ、分割の理由、演出の連続性を記録してください。生成側dry-runと実音声・試聴は別欄にします。場面の解釈や発話分割が別のLLMと違うだけで失敗とは判定しません。
