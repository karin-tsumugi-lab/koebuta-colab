# CLI v1.1.0: 自動参照と生成前の確認

## 声の選び方

- `voiceMode` を省略すると、未指定の参照を自動準備する。既存の共通WAV・話者WAVがあれば、そのWAVを使う。
- `voiceMode: design` は共通声と既定割当の参照なし指定。人物別では `speakerVoices` の個別指定が優先され、`design` はその話者の参照なし指定になる。シード違いの声候補比較では明示的にdesignを指定する。
- `voiceMode: clone` でもWAVが未指定なら自動準備する。指定したファイルが存在しない、WAV形式が破損している場合は生成前に停止する。発話内容や声質は検査しない。
- `autoReference: false` は従来の厳密な参照指定に戻す。cloneで未指定ならエラー。確認の省略とは別設定。
- 人物別では未設定の話者ごとに準備する。同じ未設定プロファイル名を使っていても、異なる話者を同じ声にまとめない。
- 一人朗読では全発話が共通の声グループになる。`voices.voice_a` が共通WAV。共通WAVがあれば話者別WAVより優先する。共通WAVがなく話者別の割当やWAVが残っている場合は競合エラーとし、共通WAVの指定か人物別への変更を求める。

## 参照文

同じ声グループの分割前の原稿発話が複数ある場合、20～100文字、感情neutral、感嘆符・疑問符・三点リーダー・連続ピリオドを含まない本文から60文字に最も近い文を選ぶ。同点なら原稿順。読み変換後の本文を使い、区切りは除外する。長い1発話がTTS用に複数の片へ自動分割されても、単一発話として参照なしで生成する。内容が平常かどうかは保証できないため、生成前に選択文を表示する。

選び直す場合は設定へ `"autoReferenceSegments": {"話者ID": "発話ID"}` を指定する。一人朗読のキーは `shared`。dry-runで表示する分割後の発話IDを使う。条件を満たさない文・存在しないID・単一発話・明示WAV付き・design指定への選択はエラー。

選択した文を声質説明付き、感情・演技なし、参照なしで先に生成する。そのWAVを保存してから、選択文を含む本編の全発話を原稿順に通常の感情・演技設定で生成する。共通声の説明は `baseCaption`、人物別は各話者の `voice_caption` を使う。声質説明が空なら停止する。

単一発話、または適切な候補がない声グループは、参照なしで直接生成する。発話間の声の一貫性が保証できない旨を表示する。参照なしで複数発話を生成しても、同じ声とは断定しない。

## 確認は1回

Colabへの接続・CU照会・出力フォルダー作成より前に、声グループ、方式、参照文、本編発話数、自動参照を新規作成・変更した場合に生成する最大発話数を表示し、`この内容で生成しますか？ [y/N]` を1回だけ尋ねる。`y` で実行、それ以外や入力終了では取りやめる。

- `--yes`（`-y`）または設定の `"confirm": false` で確認を省略する。計画の表示は残る。
- 入力不正・競合・指定WAVの欠落や破損を、確認省略によって許容しない。
- 非対話実行では `--yes` または `confirm: false` がなければ実行前にエラーとする。
- `--dry-run` は確認せずJSONの計画だけを返す。ネット接続・GPU処理・出力作成は行わない。未生成参照を使う本編のfingerprintはnullで、実WAVのハッシュ確定後にworkerが最終値を作る。

AI向けの基本手順は「dry-runの計画を確認 → 利用者が承認した範囲で `--yes` を付けて生成」。例外を勝手に解決しない。

## 再開と保存

自動参照はジョブ内の `references/` と `references.json` に保存する。メタデータには参照文・選択発話・声質説明・seed・steps・固定モデル/codec/upstream等の実行条件・WAVハッシュを含む。同じ遠隔ジョブで再実行した際は、条件とWAVの検証が一致した参照を再利用する。

条件が変われば新しい参照を準備し、その参照に依存する本編音声だけキャッシュを無効にする。旧WAVは上書きしない。間だけの変更では参照と発話音声を再利用し、結合し直す。現在使う保存済み参照が破損していた場合は、別の声を自動生成せず復旧を求める。正常な指定WAVへの差し替えやdesignへの変更で使わなくなった参照は、今回の生成・回収の検証対象から外す。履歴自体は回収ジョブ内に残す。

準備途中で中断しても、保存を完了した参照は次回再利用できる。本編は必要な参照がすべて揃ってから始まる。回収ZIPには参照WAVとメタデータも含め、完成時に使用中の参照のハッシュとフレームを検証する。入口の `references/` と `references.json` には、現在使う参照だけを保存する。参照を使わなくなった場合は空のメタデータを保存し、参照フォルダーは作らない。

遠隔キャッシュの有無と実際の再生成件数はworkerで確定する。ホストの確認画面では最大対象数として示し、正確なキャッシュ命中数とは扱わない。ホストの `--out` は再実行時も新しい場所を使う。同じ生存ランタイムの同じ `--job` を指定する。切断直後は重複実行を避け、まず既存の回収コマンドで状態を確認する。別ランタイムへのジョブ復元は今回追加していない。
