# Koebuta Scenario Inspector v3 利用案内

`Koebuta_Scenario_Inspector_v3.html` は、単一HTMLファイルでシナリオJSON（`schema_version: 1`）の話者、原文、読み上げ文、追加ルビの採用状態、感情、演技指示、発話後の間、編集指示メモ（`notes`）、参照音声WAVを確認・編集するツールです。

※ エディタ上では音声合成は行いません（割り当てた参照音声WAVの試聴は可能です）。音声合成には [CLI（`cli/irodori_generate.py`）](../cli/README.md) を使用します。

---

## 1. 開く・保存する

`Koebuta_Scenario_Inspector_v3.html` を手元のブラウザー（Chrome / Edge 推奨）で開きます。

- **JSONを開く / 保存する**: 単体の `scenario.json`（例：`works/my_book/scenario.json`）を読み込んで編集し、上書き保存または別名保存できます。
- **作品フォルダーを開く / 保存する**: File System Access API 対応ブラウザーでは、`scenario.json` と `voices/`（参照音声WAV）を含むフォルダーごと開いて保存できます。
- **Undo / Redo**: 編集操作を元に戻せます。作品フォルダーの保存時と作品の再読み込み時に履歴がクリアされます。

> 画面上部の検査結果を確認し、JSONを保存してから、そのファイルでCLIの `--dry-run` を実行してください。編集途中のJSONも確認のうえ保存できます。

---

## 2. 画面上でできる操作と、JSON側で修正する項目

現行の Scenario Inspector v3 で**画面から直接操作できる項目**と、**JSONファイル側で修正する必要がある項目**は次のとおりです。

| 対象 | 画面上でできること | 画面上の制約・JSON側で直す項目 |
|---|---|---|
| **話者一覧（左パネル）** | 表示名（`name`）、種別（`narrator` / `character`）、声の特徴（`voice_caption`）、普段の話し方（`acting_description`）、人物像（`bio`）の編集 | 新規話者IDの追加・削除や `speaker_id` キー名の変更はJSON側で行います |
| **原文（`text`）と読み上げ文（`tts_text`）** | 各発話の `text`・`tts_text` の編集、および `tts_text` カーソル位置への非言語音絵文字（`😮‍💨` `🤭` `⏸️` 等）の挿入 | その発話に `koebuta_added_ruby`（追加ルビ）がある場合、`text` を画面で書き換えて文字数が変わると追加ルビの `start / end` 位置がずれます（下記参照） |
| **追加ルビ（`🔖` / `koebuta_added_ruby`）** | 既存の追加ルビについて、採用状態のプルダウン（`自動`=`auto` / `仮名`=`kana` / `元表記`=`surface`）を切り替える | **追加ルビの新規追加・削除・対象範囲（`start / end`）や読みの変更は画面からはできません。** `text` 編集によって位置ずれエラーが出た場合、`tts_text` を修正しても `koebuta_added_ruby` の位置エラーは解消されないため、JSON側で `start / end` を修正するか該当要素を削除してください |
| **編集指示メモ（`notes`）** | 「編集指示」欄での自由記述メモ（`[効果音] 直後に水音` 等）の追加・編集・空欄化による削除 | TTS生成には渡されません（人間の音声編集・ミックス用メモとして往復保存されます） |
| **感情・演技・間** | 34種の `emotion` 選択、発話ごとの `acting_description`、発話後の間 `pause_after_ms`（個別指定と自動計算へのリセット） | CLIで実際に生成する際の共通休止や感情・演技のON/OFFは別ファイルの `settings.json` で指定します |
| **発話の分割** | 1件の発話を自然な切れ目または指定文字位置で2発話に分割する（追加ルビは該当側へ引き継がれ `start / end` が自動更新され、`notes` は元の発話ID側に残ります） | **原文 `text` とは異なる手動編集済みの `tts_text` がある発話**や、ルビ・追加ルビの親文字の途中では画面上で分割できません。先に `tts_text` を空（未指定）に戻すか、JSON側で分割してください |
| **発話の結合** | 連続する発話を選択して1発話に結合します | 追加ルビまたは編集指示がある発話では、強制結合を選んでも停止します。JSON側で結合し、新しい本文に合わせてルビの位置と編集指示の配置を確認してください。 |

## 3. 原文照合と許可済み見出し改変の扱い

シナリオJSONに原稿全文 `source` が含まれている場合、エディタおよびCLIは各発話の `text` を先頭から順番に部分照合し、不一致があれば警告を表示します。

- シナリオ作成時にタイトルや章見出しの朗読文への改変（例：「太宰治」「女生徒」→「これから、太宰治の『女生徒』を朗読いたします。」）を許可していた場合も、機械照合では原文不一致の警告が出ます。
- 警告が出た箇所が「許可した見出し改変」であるか、「意図しない本文の脱落・改変」であるかを確認してください。警告を消すために `source` を書き換えたり削除したりしないでください。
