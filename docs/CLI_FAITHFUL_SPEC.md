# Koebuta CLI 新仕様整理 v0.2

更新日：2026-11-16（日本時間）。v0.1の未確定5項目に対するユーザー判断と、委任された細則を反映した実装前仕様。以下の新しい動作・引数はまだ実装していない。CLIのリリース番号は別途定め、シナリオ交換形式は `schema_version: 1` を維持する。

実装の確認基点：`karin-tsumugi-lab/koebuta-colab` の `9166f81892b725359a6f8368fdab3b70479a7b95`。今回は仕様書と静的な影響調査のみを更新し、コード・PRは変更しない。

> 2026-11-16の実装基準。第8節の「現行」は実装前の影響調査です。実装後の状態・検証・未実施範囲は [検証記録](CLI_FAITHFUL_VALIDATION.md) を参照してください。

## 1. 基本方針と今回の決定

CLIは完成したシナリオを忠実に生成する実行役とする。AIが認識する発話と、生成・再生成の対象を一致させる。

- 自動分割・自動結合・本文補完・演出や読みの再判断は行わない。
- 入力の発話ID・順序・話者・原文・読み上げ文・位置指定タグを保持する。
- 明示されたTTS片には対応する。CLIが新しい片を作ることはない。
- 発話IDまたは明示TTS片を選択して生成できる入口を追加する。完成音声への自動差し替え・採用管理は初回改修に含めない。
- 休止・生成設定・検査の細則は本書で定める。入力不正はID付きで返し、品質の懸念は警告する。
- Colab接続・GPU実行・回収・保存・停止の仕組みは維持する。
- 新仕様の入口と下位の計画・遠隔実行を揃えて改修し、旧入口・他構成への変更を自動波及させない。

新しい依頼プロンプトによって不備が減ることを前提に設計するが、入力検査は残す。不備の消失や音質改善を実証済みとはしない。

## 2. 入力と処理の流れ

### 入力

| 入力 | 扱い |
| --- | --- |
| シナリオ | JSON交換形式v1。必須項目と意味を維持し、生成計画とは分けて保持する |
| 生成設定 | シナリオと別JSON。声、モデル、seed、steps、感情・演技の反映、共通休止等を指定する |
| 参照音声 | 既存の声の割り当てと転送方法を土台にする |
| `source` | 任意。提供された元原稿だけを保持する。省略時に発話や話者名から創作・補完しない |
| `koebuta_tts_parts` | 既存の任意拡張を読み、指定された境界を尊重する。新たな標準必須キーは作らない |

作品解釈、場面演出、朗読形式に応じた配役、意味に沿う発話分割、読み、見出し改変の許可確認は、前段のAIまたはユーザーが担当する。

### 実行順序

1. シナリオ・設定・対象指定を読み込む。
2. 全シナリオの構造、ID、話者参照、発話／区切りの型とTTS片の整合性を検査する。
3. 読み上げ文、明示TTS片、休止、生成設定を決定的に解釈する。
4. 対象発話・対象片を選択し、声とファイル参照、生成条件を確認する。
5. 元の発話IDと対応する生成計画・診断を作る。dry-runならここで終了し、ネットワーク・GPU・出力フォルダーの作成を行わない。
6. 実行依頼時にColab準備・生成・回収・検証・保存へ進む。
7. 選択範囲、完了範囲、未完了範囲、保存先、停止の成否を区別して報告する。

## 3. 発話と明示TTS片

### 読み上げ文の決定

1. 有効な `tts_text` があれば、発話全体の完成した読みとしてそのまま使用する。
2. なければ指定されたルビ形式の決定的な変換を行う。
3. 変換不要なら `text` を使用する。

読みの推測、固有名詞の補正、表記の平易化は行わない。未知のルビ形式や解釈できない記法を勝手に別形式へ置き換えない。入力の空・空白だけの `tts_text` は仕様書に従い未指定として扱い、警告する。

### TTS片の規則

- 片の指定がなければ、一つの発話を一つのTTS要求へ対応させる。改行・句読点・80文字を理由に分割しない。
- `koebuta_tts_parts` を使う場合は、既存拡張に合わせて2個以上の、空白だけではない文字列の配列とする。有効な発話全体の `tts_text` も必要で、全片の連結値がそれと完全一致しなければエラーとする。
- 片の前後の空白・改行・位置指定タグを勝手に削除しない。結合文字・異体字セレクタ・ZWJで構成される文字や、認識済みタグの途中で片が切れていればエラーとし、分割位置をユーザー側で直す。
- `text`、`tts_text`、親発話ID、台本の行数を変更しない。区切り項目へのTTS片指定はエラーとする。
- 各片は親の話者、感情、演技、声と生成条件を継承する。有効な感情タグは各TTS要求の先頭へ適用する。位置指定タグは入力された片の中の位置を保つ。
- 片間にCLIが追加する休止は0ms。発話後の休止は最後の片の後に一度だけ適用する。
- 片がエンジンの実際の入力限界を超えても再分割しない。親発話ID・片番号を示して修正を求める。

### IDと生成記録

計画上は親の `segment_id` と1始まりの `part_index` を別々に保持する。片なし発話は `unit_id = 発話ID`、片あり発話は表示用に `発話ID#1`、`発話ID#2` を使う。`#`は選択・表示用であり、シナリオのIDへ書き戻さない。シナリオIDは標準の英数字・`_`・`-`を使用する。

入力シナリオ、生成計画、音声ファイルの対応を記録する。片の数や境界が変わった場合は計画の識別情報も変え、古い片を同じ位置だからという理由で再利用しない。

## 4. 再生成の対象指定

### 初回改修に含める範囲

`irodori_generate.py`へ `--ids` を追加する。選択対象を指定して、新しいジョブ・新しい出力先へ音声を生成する。既存成果物は変更しない。

| 指定例 | 意味 |
| --- | --- |
| 指定なし | 全発話・全片を生成 |
| `--ids t001` | 発話t001全体。明示片があれば全片 |
| `--ids t001,t003` | 二つの発話全体 |
| `--ids t003#2` | t003の明示片2だけ |
| `--ids t001,t003#2` | 発話全体と片の混在指定 |

複数指定は元のシナリオ順・片順へ並べ、重複選択は一度にまとめる。存在しないID・片番号、区切りID、空の指定、不正な選択記法はGPU実行前のエラーとする。

シナリオ全体の構造は検査するが、参照WAVの存在確認・転送・生成は選択範囲に必要なものだけを対象にする。全作品用の声設定が残っていても、非選択話者に属する設定という理由だけで拒否しない。未登録話者への設定など、構造上の誤りは拒否する。

### 結果と非対象範囲

- 選択生成の `result.wav` は選択範囲だけをつないだ音声で、作品全体の更新版ではない。選択された片が隣接しない場合も、元の間隔を復元したと見せず、試聴用の抜粋として扱う。選択範囲の境界休止の規則は第5節。
- 記録へ `scope: full / selection`、要求された親ID・片、生成対象数と完了数を持たせ、画面にも「選択範囲の生成完了」と表示する。これらは計画・実行記録の項目で、シナリオJSONの新キーではない。
- 親の全片が揃っていない場合、親発話全体が完成したとは記録しない。選択生成の完了と、作品全体の完了を分ける。
- 既存の完成WAVへの自動差し替え、候補の採用・比較管理、旧実行結果を取り込む自動再結合は初回改修に含めない。
- 初回の対象指定は新しいジョブへ生成する方式で、既存ジョブの強制再生成を切り替える新しいフラグは不要。下位CLIの既存 `--regenerate` は旧経路の機能として維持する。

### 実装難易度の評価

公開コードの静的調査では、下位の `irodori_colab_cli.py`・workerに既存の `--ids`・`--regenerate`、jobsに選択生成の処理がある。上位入口へ対象指定を通す土台はあり、対象発話だけのJSONを毎回作る必要はなくせる。IDと明示片の対応・選択範囲の完了記録・回収判定を揃える作業は必要で、単なる引数追加だけではない。

対象指定は実装に含める。完成音声への自動差し替えまで広げると、旧音声の取り込み・条件整合・採用・再結合が増えるため、そこは別機能とする。この評価はコード調査による見積もりで、実装・実GPU試験済みではない。

## 5. 区切り・休止の確定規則

演出上の間を推測せず、明示された値と共通設定から一意に計算する。

### 入力と上限

- `separator`は音声要求を作らず、話者なし・空または省略textを受け付ける。
- 原稿の区切り記号は保持する。記号列を区切りへ自動分類しない。
- `pause_after_ms` は真偽値を除く0〜10000の整数ms。0も明示指定とする。現行CLIの範囲を維持し、値を丸めたり切り詰めたりしない。
- 共通休止 `pause` は0〜10の有限な秒数、未指定時0.28秒。内部ではミリ秒へ決定的に換算し、音声のフレーム丸めは出力時にだけ行う。
- `source`の改行数や `blank_lines_after` から休止を追加しない。`blank_lines_after` は保存する参考情報とし、正の値があれば「休止への自動反映なし」とまとめて通知する。
- 新入口では `textOptions.blankMode` のgroup/count、`symbolSeparators: true`、読みの自動補正のselective/allは非対応としてエラーにし、明示的な間・区切り・完成tts_textへ直す方法を示す。既定のoff/falseは受け入れる。設定が与えられたのに黙って無視する運用はしない。

### 一つの境界に適用する間

| 状況 | 採用する間 |
| --- | --- |
| 直前の発話に明示pause_after_msがある | その値。0も最優先 |
| 発話に明示値がなく、次の発話までの区切りに明示値がある | その区間の明示値の最大値。合算しない |
| 発話にも区切りにも明示値がない | 共通休止 |
| 明示TTS片の途中 | 追加休止0ms |

例：発話に0ms、続く区切りに900msなら0ms。発話に指定がなく、連続する区切りに900ms・1200msなら1200ms。一つの境界に複数の明示値があり、優先規則で採用されなかった値があれば、その境界の診断として知らせる。

冒頭は共通休止を入れないが、冒頭の区切りに明示値があればその最大値を先頭無音にする。末尾も共通休止を入れず、最後の発話または末尾区切りに明示値がある場合だけ、同じ優先規則で末尾無音を入れる。区切りだけで発話のない入力は生成対象なしのエラーとし、無音作品を作る機能は追加しない。

選択生成では、選択された各片が親の最後の片かどうかを元の計画で判断する。途中の片の後には発話後休止を付けず、最後の片なら上の規則で確定した親の休止を使う。非選択音声の時間は補間しない。選択音声間では左側の選択単位に付く休止を一度だけ使い、抜粋全体の先頭・末尾に共通休止は加えない。作品冒頭の無音は冒頭単位を含む場合だけ、作品末尾の明示無音は末尾単位を含む場合だけ反映する。

## 6. 生成設定・検査・診断

### 新入口の生成設定

- 新しい忠実生成の入口では、未指定時の `emotion`・`acting`・`narratorEmotion` はすべてtrueとする。シナリオに書かれた演出を既定で反映するための変更であり、移行案内とdry-runに明記する。
- ユーザーがfalseを明示した場合は、その値を尊重する。非neutralの感情や演技説明が抑制される場合、対象IDと有効な設定を警告する。勝手にtrueへ変更しない。
- seed・steps・声の割り当て・モデルなど、上記以外の既定値は現行の新入口の設定を維持し、同時に変更しない。旧入口の既定値は変更しない。
- 感情タグの適用、演技Captionの組み立て、明示ルビの変換は指示の実行であり、意味や演出の再判断とは区別する。

### 検査と表示

| 区分 | 判定 |
| --- | --- |
| エラー | 構文・型・必須項目・ID・話者参照の不正、空の発話、未知の項目種別、未知の感情ID、明示TTS片の不整合、不正設定、必要なファイルの欠落、対象指定の不正 |
| 警告 | 短文、長文、生成設定による演出の抑制、原文照合の不一致、効果を持たない空行情報等 |
| 情報 | 原稿未提供で照合未実施、全体／選択の範囲、使用する既定値、出力・生成単位の対応 |

エラーが一件でもあればGPU生成を開始しない。検出できる入力エラーはまとめ、発話ID・片番号・項目名・理由を示す。不正発話を黙ってスキップしない。実行時にだけ判明するバックエンドの入力限界・モデルエラーも対象単位とともに報告し、自動分割による再試行はしない。

`source`がある場合は順序付き部分照合を行い、最初の不一致を非停止の警告にする。完全性の証明ではなく、見出し改変の許可を判定しない。`source`がなければ照合未実施とする。元原稿や本文を書き換えて警告を消さない。

文字数は実際の読み上げ文字列を対象に、既知の絵文字タグと空白類を除いたUnicodeコードポイント数で算定する。概算指標でありモデルのトークン数ではない。10未満を強い警告、10〜14を短文警告、15〜19と80超を推奨範囲外の通知とし、20〜80に合わせた補正はしない。非言語タグだけの完成読みも長さだけで削除・水増ししない。

診断は計画に `level`・`code`・`segment_id`・任意の `part_index`・`field`・`message` を持たせる。標準出力のJSONと標準エラーの人向け表示を分け、成功時にも警告を確認できるようにする。診断コードは `E_STRUCTURE`、`E_REFERENCE`、`E_PARTS`、`E_SELECTION`、`E_SETTINGS`、`W_LENGTH`、`W_DIRECTIVE_DISABLED`、`W_SOURCE_MISMATCH`、`W_LAYOUT_IGNORED`、`W_PAUSE_CONFLICT`、`I_SOURCE_UNCHECKED`を基本とする。これはシナリオ構造の変更ではない。

## 7. 出力・保存・互換性

入力シナリオは上書きしない。計画・生成要求・WAV・親発話／片の対応・生成条件・成否を別記録で保持する。既存の完成WAV、発話別WAV ZIP、計画・進捗・回収・停止記録の役割は維持する。

明示片がある場合は片WAVを追跡可能にし、親の全片が揃った場合だけ親発話の完成WAVを作れるようにする。片の候補が一つできただけで親全体を完成扱いにしない。全編結合は入力順・片順と確定した休止だけを使用する。

旧自動分割で発行したIDや旧計画を、新しい明示片のIDへ自動移植しない。生成計画・キャッシュの実行契約に新しい識別を持たせ、旧キャッシュを一致と誤認しない。旧結果は保持し、新しい出力先で実行する。

処理に必要なモデル・音声の権利、認証、GPU・費用・転送の承認範囲、回収・保存・停止の条件は既存どおり。音声検証と試聴、生成成功と停止失敗を区別する。

## 8. 静的な影響調査と移行範囲

公開コードの呼び出しを調べた結果、自動分割は上位の一か所だけではなかった。CLI内の呼び出しと、CLI外の追跡済みPython・Notebook・HTMLソース22ファイルの直接参照を確認した。

| 確認箇所 | 現行の呼び出しと移行上の注意 |
| --- | --- |
| `cli/irodori_generate.py` | `load_inputs`でprepare_projectを実行。その後sampling_planで計画を作る。新しい入力アダプターと計画へ差し替える |
| `cli/irodori_cli/worker.py` | 遠隔synthesizeでもprepare_with_mapping・expand_idsを実行し、プロジェクトを書き戻している。新経路ではここでも分割・ID展開・入力書き戻しを行わない |
| `cli/irodori_cli/__main__.py` | planとsynthesize/runにも同じ分割呼び出しがある。共有関数を一律変更すると旧入口へ波及する |
| `cli/irodori_cli/core.py` | normalize_project・import_analysis・sampling_planが複数入口で共有される。区切り・任意source・TTS片・新しい既定値は新経路の入力・計画アダプターで扱い、旧利用者の挙動を暗黙に変えない |
| `cli/irodori_cli/jobs.py` | 選択・キャッシュ・結合の基盤は再利用可能。ただし明示片、全体／選択の完了判定、冒頭・末尾の明示無音は追加対応が必要 |
| `cli/irodori_colab_cli.py` | 下位のids・regenerate転送がある。親IDと片IDの新しい対応、選択計画、遠隔実行の契約を揃える |
| ルートの回帰試験 | `test_v2_emoji.py` がCLIのsplit_segmentsを直接参照する。旧分割関数を残す場合も回帰対象にし、新経路の自動分割廃止を別の受け入れ試験で確認する |
| Notebook・HTML・Fast | 本調査で共有CLI分割関数への依存は見つからない。Notebook生成元はCLI絵文字台帳を読むが、今回は台帳を変更しない。他構成のコード・既定値・挙動は変更しない |

初回は `irodori_generate.py` の新仕様と、それを実行する下位の新経路を対象にする。ホストと遠隔で同じ決定的な計画処理・契約を使い、遠隔側が旧自動分割へ戻ることを防ぐ。旧入口は従来の経路を維持し、全CLIの一括刷新・LLM分析機能の削除・Notebook改修は同時に行わない。

「他構成への依存が見つからない」はリポジトリ内の静的調査結果であり、外部の独自改変や未公開の利用者まで影響がない保証ではない。実装時はホスト／遠隔計画の一致、新経路の受け入れ試験、共有基盤と旧入口の回帰を確認する。

## 9. 実装時の受け入れ条件

- 改行入りの短い見出しが、明示片なしなら一要求のまま。80文字超も実際のエンジン限界内なら自動分割しない。
- 明示片は指定どおりの文字列・数・順序で生成し、親の行数・ID・text・tts_textを保持する。片の連結不一致やタグ途中の境界では生成前に停止する。
- 発話全体・片単位・混在選択・重複選択を正しく解決し、対象外のWAVを生成・転送・上書きしない。存在しない対象はエラー。
- 全体生成と選択生成の完了を区別し、非選択片を生成せずに「親の全片完成」「作品全体更新済み」としない。
- 話者なし・空本文の区切りに音声要求を作らず、0ms、連続区切り、競合、冒頭・末尾、片内0ms、選択抜粋の休止を規則どおり処理する。
- 感情・演技の未指定時の反映と明示falseの尊重を確認し、各片でも指定どおりに適用する。
- 原稿未提供と部分照合の不一致を正しく診断し、原文を補完・修正しない。
- 不正なID・型・参照・設定・選択・TTS片ではGPU実行前に停止し、入力を黙って救済しない。
- dry-runがネットワーク・GPUを使わず、対象範囲、既定値、診断、親と片の対応を示す。
- ホストとColab側の計画が一致し、下位で再分割されない。旧入口・既存回収・キャッシュ・停止処理の回帰も確認する。

仕様上の5論点の方針は本版で整理した。バックエンドの実際の入力限界や個別APIとの接続条件は、実装時に使用版から確認して記録する。新仕様のコード変更・回帰試験・実GPU生成・実ブラウザー操作は未実施。
