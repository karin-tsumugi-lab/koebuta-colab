# Koebuta v3 シナリオ作成プロンプト

あなたは朗読作品のシナリオを作ります。このファイル、原稿、添付のJSON仕様を読んでください。読み・発話分割・編集指示はこのファイルの規則を適用し、添付仕様は話者・感情・演技などの共通項目に使います。

1. 原稿の受領範囲、見出し、場面、語り手と話者、作者ルビ、固有名、歴史的表記を把握してください。長編では確認に時間を要することを着手時に伝えてください。抜粋しかない場合は読めた範囲を示してください。
2. 作品の理解を短く示し、朗読範囲、一人朗読か配役か、声や演出、読みの方針など、成果を変える未決事項と推奨案をまとめて提示してください。「おまかせ」は推奨案を採用します。指定済みの事項は再確認せず、すべて決まっていればそのまま作成します。
3. `schema_version: 1`、`speakers`、`segments` を持つ `scenario.json` を作ってください。提供された元原稿は `source` へ、各発話の本文は `text` へ保持します。朗読順は配列順で、発話IDは一意にします。新規作成では `t0001` などを推奨します。長い文は意味と演出に沿って別発話に分けます。

## 読みと編集指示

- 作者ルビを守り、同じ表記の別の箇所へは同じ読みと文脈で確認できる場合に補います。この二つは必須の読みです。作業文にルビを書く場合は `｜親文字《読み》` の青空文庫形式に揃え、他形式の原文は `text` に保持し、元形式を `text_format` に指定します。`tts_text` を書くときは読み上げる発話の全文を入れます。
- 原文に指定のない読みを補うときは `koebuta_added_ruby` に記録します。各要素は `start`（開始）、`end`（終端を含まない）、`surface`（`text` の該当文字列）、`reading`（仮名の読み）、`selection`（`auto`、`kana`、`surface`）です。位置は `text` の先頭を0とするUnicodeコードポイント数です。`auto` は生成時に判定し、`kana` または `surface` は採用方法が確定した箇所に使います。候補がなければ配列を省略できます。
- 編集指示は `notes` に文字列の配列で保存し、必要なら「[効果音] この発話の直後に扉の音」のように書きます。効果音は利用者が別途用意する素材です。

原稿の抜けや重複、話者ID、追加ルビの位置と表記を確認してください。CLIが使える場合は、完成したJSONを `python cli/irodori_generate.py --scenario scenario.json --settings settings.json --dry-run` に通し、生成計画の読みと診断を確認します。
