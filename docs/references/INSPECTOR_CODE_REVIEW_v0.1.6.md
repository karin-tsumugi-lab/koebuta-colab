# Koebuta Scenario Inspector v0.1.6 コードレビュー

レビュー対象：`core.mjs`, `app.js`, `shell.html`, `build.mjs` とテスト群。前回v0.1.5の指摘5件について再現テストを作成し、修正後に回帰試験を実施。

## 前回の指摘と結果

| 重要度 | 項目 | v0.1.6の判定 | 具体的な検証 |
|---|---|---|---|
| P1 | WAV差し替えでUndo/Redoが実体を復元しない | **修正** | `snapshot`/`restoreSnapshot` にWAV Mapを含め、旧・新WAV実体をUndo/Redo前後で比較 |
| P1 | 通常結合で後続行の未知属性が消失 | **修正** | 未知属性付きの通常結合が拒否されること、強制結合のバックアップに元属性が残ることを確認 |
| P2 | `source` 原文不一致が表示されない | **修正** | 順序付き部分照合、不一致警告、実作品54件・重複文章の正常例を検証 |
| P2 | WAV複数ファイル保存の途中失敗 | **緩和** | 事前検査とバックアップ取得、JSONを最後に保存、途中失敗時のWAV復旧と新規WAV削除を模擬試験 |
| P3 | WAVのヘッダしか見ない | **修正（サイズ制限あり）** | チャンク不正の拒否、PCM検査、Chromiumで64MiB以下のWAVを実デコード |

### データ保全の判断

- 通常結合で後続行に任意の未知フィールドがある場合、何らかの統合規則を勝手に作るより**処理拒否**とし、強制結合へ案内します。
- 強制結合は従来どおり、取り込む発話の完全データを `koebuta_merge_backup` に残します。
- WAVの保留ファイルは`File`への参照を`Map`のスナップショットに保持し、オブジェクトのJSONシリアライズはしません。
- 作品フォルダへの保存後はWAVの外部状態が確定するため、過去のUndo/Redo履歴をクリアします。

## 新たに見つけた／残っているリスク

**P2：複数ファイルの完全な原子性は実現できません。** ブラウザFile System Access APIには、複数WAVとJSONの単一トランザクションがありません。通常のJavaScript例外には復旧処理を行いますが、電源断・ブラウザ強制終了では復旧コードそのものが走りません。また復旧中に権限が取り消されると一部ファイルが戻らない場合があります。対応は、作品フォルダの世代バックアップや別環境でのファイル管理が必要です。

**P2：外部更新との競合検出が未実装です。** Inspectorを開いたまま別アプリで同じ`scenario.json`やWAVを更新すると、Inspectorが再保存した際に新しいデータを上書きする可能性があります。使用中は同じフォルダを別アプリから編集しないでください。今後はロード時ハッシュと保存直前ハッシュを比較する方式を検討してください。

**P3：大容量WAVの音声デコード未検証。** 64MiB超のファイルはヘッダ/チャンク構造のみ検査します。音声データ内部まで正常か保証できません。

**検査の限界：** `source` は順序付き部分照合のみで、原稿全文の完全なカバレッジや重複文の曖昧性を保証しません。現行Koebutaと同じく完全整合の証明ではありません。

## 実行したテスト

- `node test-core.mjs`：既存コア27件成功（22件＋追加5件）
- `node test-ui-dom.mjs`：従来UIの模擬操作成功
- `node test-review-v016.mjs`：新規レビュー専用10件成功。WAV Undo/Redo、保存失敗時の復旧、結合の未知属性と`source`照合を含む
- `node test-zip.mjs`：ZIP構造の基本検査成功
- `node test-browser-sticky.mjs`：Chromium上で固定UI・選択解除・実作品自動整形・休止編集・強制結合・WAVデコードを確認

**未実施：** 実OSのディレクトリピッカーを用いた読み書き、Chrome/Edgeの `file://` 直接起動、電源断などの強制終了試験、およびPython版Koebutaとの全組合せ比較。

## 次に推奨する改善

1. 保存先の外部変更検知（mtime/内容ハッシュ）と衝突時の保存停止。
2. 作品フォルダの自動世代バックアップ（WAVの大きさ・保存容量と相談）。
3. 実機上でのファイルアクセスAPI受け入れテスト。

現時点の位置づけ：**v0.1.5の最優先2件は修正済み。試作・検品に利用可能だが、唯一の原本を直接上書きする運用にはまだ推奨しない。**
