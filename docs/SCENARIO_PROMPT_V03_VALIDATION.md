## 許可済み見出し改変と現行実装

追加再現の入力：`source`は `太宰治\n女生徒\n雨が降っていた。`、最初の発話の`text`は `これから、太宰治の『女生徒』を朗読いたします。`、次は `雨が降っていた。`。すべて同じnarrator IDで、`source`は変更しなかった。rootの作品名フィールドだけを変更する試験とは区別する。

| 対象 | 実測・根拠 |
| --- | --- |
| Inspector | HTMLの`diagnostics`は最初の発話へ`原稿全文 source に発話原文を順序どおり見つけられません（部分照合・要確認）`をwarningで返した。次の発話には既存UI基準の短文notice（8文字・12文字未満）。この12文字はInspectorの判定値であり新しい推奨範囲ではない |
| CLI実入口 | `irodori_generate.py --dry-run --no-usage`、設定`{}`でも終了0、stderrなし。紹介文と本文の要求2件。`load_inputs`→`new_project`→`import_analysis`→生成計画の経路は、全発話が本文付きの場合に元の`source`との部分照合を行わない。`scenario_compile.py`の別の原稿検証経路と混同しない |
| Notebook v2 | Notebookのコードセル5の`validate_project`は最初の発話に要確認を返す。`require_ready`を実際に呼ぶと`生成前に1件の項目を確認してください`のValueError。`notebook_v2_ui.py`の読み込みが`require_ready`を`notebook_v2.load_project`へ渡し、`validate(project)`で停止する経路も確認 |

許可を自動認識・解決する標準フィールドは存在しない。Inspectorの指摘は許可記録と照合できるが、Notebookは現行のままでは読み込みを完了できない。この点を[エディタ案内](EDITOR_GUIDE.md)と01・02・03B、READMEへ明記した。

Notebook向けは見出しも原文保持で運用する。許可済み改変を使うCLIでは別途原稿照合を行う。`source`を消す・改変文へ差し替える・検証を無効化する回避策は採用しない。Notebookで許可済み差分を扱う方法の設計・実装は別途判断が必要であり、本作業ではコードを変更しない。
