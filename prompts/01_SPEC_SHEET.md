# Koebuta v3 朗読シナリオJSON仕様書

- バージョン：Koebuta v3（JSON内のフォーマット識別子は `"schema_version": 1`）
- 役割：シナリオJSONの**意味とデータ構造**を定める。LLMへの依頼手順は [02_CHAT_PROMPT.md](02_CHAT_PROMPT.md)、エディタ操作は [EDITOR_GUIDE.md](../docs/EDITOR_GUIDE.md)、CLI生成設定は [cli/README.md](../cli/README.md)、ルビ・編集指示の詳細規則は [V3_SCENARIO_SPEC.md](../docs/V3_SCENARIO_SPEC.md) を参照。

## 1. 基本方針

1. **生成側には簡潔な形式を求める。** LLMにハッシュ計算、厳密な文字数計算、未実施の機械検証結果の申告を要求しない。作品全体の理解と場面演出を先行し、利用可能な範囲で原稿と出力を見直す。不明な解釈は無理に確定させない。
2. **受け取り側は寛容に解釈する。** 未知の項目や任意項目の欠落・不正値は、可能な限り無視または既定値に置き換え、使用した代替処理を必要に応じて通知する。
3. **原文と話者の対応を黙って改変しない。** 本文の削除、補完、置換、順序変更、別の話者への割り当ては自動で行わない。シナリオ作成時の見出し類の限定的な改変は、5節の明示許可条件に従う。
4. **読み込みと音声生成を分離する。** シナリオの一部に問題があっても編集用に保持してよい。ただし音声生成に必要な情報が確定しない発話は、解決するまで生成しない。
5. **作品の規模を形式で制限しない。** 話者数、発話数、本文文字数、JSON全体の容量に仕様共通の最大値を設けない。アプリケーションは実行環境に応じた制限を設けられる。

## 2. 標準のJSON構造

```json
{
  "schema_version": 1,
  "source": "井戸から冷い水をくんだ。\n「明日、来る？」",
  "speakers": {
    "narrator": {
      "name": "地の文",
      "kind": "narrator",
      "voice_caption": "落ち着いた明瞭な声",
      "acting_description": "ゆったりとした語り口"
    },
    "aoi": {
      "name": "葵",
      "kind": "character",
      "bio": "原稿から読み取れる人物像"
    }
  },
  "segments": [
    {
      "id": "t0001",
      "speaker_id": "narrator",
      "text": "井戸から冷い水をくんだ。",
      "emotion": "neutral",
      "koebuta_added_ruby": [
        {"start": 4, "end": 6, "surface": "冷い", "reading": "つめたい", "selection": "auto"}
      ],
      "notes": ["[効果音] この発話の直後に桶を置く音"]
    },
    {
      "id": "t0002",
      "speaker_id": "aoi",
      "text": "「明日、来る？」",
      "emotion": "anxiety",
      "acting_description": "少しためらいながら"
    }
  ]
}
```

標準の出力では、トップレベルはJSONオブジェクトとし、`schema_version`、`speakers`、`segments` を含める。`source` は任意。出力に使用しない任意フィールドは省略してよい。話者の `name` と `kind`、発話の `emotion` は標準出力では必須とする。

### 2.1 トップレベル

| キー | 標準出力 | 意味 |
|---|---|---|
| `schema_version` | 必須 | 形式バージョン。現行は整数 `1` |
| `source` | 任意 | 入力原稿の全文。含める場合は空白・改行・ルビ・記号を含めて原文のまま保持 |
| `speakers` | 必須 | 話者IDをキーとするオブジェクト |
| `segments` | 必須 | 原稿の順に並んだ台本項目の配列 |

`source` を省略してもよい。長い原稿では重複出力を避けるため省略して構わない。受け取り側は `segments` を連結した文字列を「元の原稿全文」と称して `source` に補完してはならない。

### 2.2 `speakers`（話者一覧）

| キー | 標準出力 | 意味 |
|---|---|---|
| `name` | 必須 | 画面に表示する話者名。地の文では「地の文」、一人朗読では朗読者名または「朗読者」 |
| `kind` | 必須 | `narrator`（地の文）または `character`（登場人物） |
| `bio` | 任意 | 人物像。根拠のない設定を断定しない |
| `voice_caption` | 任意 | 声の特徴。声の試作やVoiceDesignに用いる説明 |
| `acting_description` | 任意 | 普段の話し方 |
| `age` | 任意 | `young_adult` / `adult` / `elderly` |
| `gender` | 任意 | `feminine` / `masculine` |
| `pitch` | 任意 | `high` / `mid` / `low` |
| `timbre` | 任意 | `clear` / `warm` / `soft` / `husky` / `bright` / `resonant` |
| `habitual_style` | 任意 | `gentle` / `measured` / `brisk` / `formal` / `casual` / `calm` |

- 話者IDは空でない文字列とし、標準出力では英数字・`_`・`-` を用いる。
- 一人朗読では `speakers` は一人（`kind: "narrator"`）とし、地の文・台詞・独白を含む全発話で同じIDを使用する。違いは演技で表現する。複数人朗読では地の文と登場人物などへIDを割り当てる。
- 複数人朗読では同じ人物には原則として同じ話者IDを使用する。**表示名が同じであっても、IDが異なれば別の話者**とみなす。

### 2.3 `segments`（台本項目）

| キー | 標準出力 | 意味 |
|---|---|---|
| `id` | 必須 | 台本項目の識別ID（新規作成時は `t0001` 等の4桁ゼロ埋め、または `t0010` 等の10刻みを推奨）。作品内で重複しない |
| `speaker_id` | 発話では必須 | `speakers` の話者IDを参照。区切りでは省略可 |
| `text` | 発話では必須 | 原稿から切り出した原文。5節の許可済み見出し改変だけを例外とする |
| `emotion` | 必須 | 発話の感情。区切りでは `neutral` を付ける |
| `acting_description` | 任意 | その発話だけの演技指示 |
| `tts_text` | 任意 | 読みや位置指定絵文字を調整した**発話全体**の読み上げ文。空文字列は有効な指定としない |
| `koebuta_added_ruby` | 任意 | AI・編集者が原文にない読みを補った追加ルビの配列（追加ルビがない発話では省略可、または空配列 `[]`） |
| `notes` | 任意 | 効果音や編集メモなど、ユーザー向けの自由記述指示の文字列配列（例：`["[効果音] 直後に水音"]`）。TTSには渡さない |
| `pause_after_ms` | 任意 | 発話・区切りの後の間。0〜10000の整数（ミリ秒） |
| `segment_type` | 任意 | `speech`（既定）または `separator`（読み上げない区切り） |
| `text_format` | 任意 | 原文 `text` のルビ形式：`none` / `aozora` / `narou` / `kakuyomu` / `pixiv` |
| `blank_lines_after` | 任意 | この項目の直後の空行数。0以上の整数 |

#### v3の生成単位とルビ・編集指示の規則

- **1発話＝1生成単位**：v3では1つの発話（segment）をそのまま1つの音声生成単位とし、個別WAVのファイル名も発話IDから始まる（例：`t0001_...wav`）。長い文章は自然な切れ目で別発話に分け、それぞれにIDを付ける。
- **ルビの扱い**：
  1. **原文にある作者ルビ**：必ず採用する。青空文庫形式（`｜親文字《読み》` または `漢字《読み》`）はそのまま解釈される。カクヨム・なろう・pixiv形式の原稿では、`text` に原文を保持し、`text_format` に元形式を指定したうえで、青空文庫形式（`｜親文字《読み》`）に変換した全文を `tts_text` に記述する（カクヨムの傍点 `《《…》》` はルビにしない）。
  2. **作者ルビと同じ表記・同じ読みを他の出現箇所へ補ったもの**：作者ルビと同様に `tts_text` へ青空文庫形式 `｜親文字《読み》` で補記してよい（必ず採用される）。
  3. **AI・編集者が独自に追加したルビ（`koebuta_added_ruby`）**：原文に指定のない難読漢字、旧仮名遣い、送り仮名・訓読みの揺れなどに補った読みは、原文 `text` のUnicode文字位置（0始まり、`end` は終端を含まない）を基準として `koebuta_added_ruby` に記録する。
     ```json
     "koebuta_added_ruby": [
       {"start": 4, "end": 6, "surface": "冷い", "reading": "つめたい", "selection": "auto"}
     ]
     ```
     - `selection` は `"auto"`（CLIの自動判定に委ねる）、`"kana"`（仮名読みに手動確定）、`"surface"`（元表記維持に手動確定）のいずれか。AIが新規作成する際の既定は `"auto"`（明らかに仮名化が必要な旧仮名・当て字等で確定させる場合は `"kana"`）。
- **自由記述の編集指示（`notes`）**：効果音・BGM・録り直しメモなどは `notes` に文字列配列として記録する。推奨書式は `"[用途] 指示文"`。本文や `tts_text` に効果音の説明文や `🔖` などの記号を混入させない。

#### 感情IDと位置指定絵文字

発話全体の感情・話し方は `emotion` に以下の34種類のIDから1つを指定する（実装正本：`cli/irodori_cli/emoji_tags.py`）。

`neutral`（平静）/ `joy`（喜び）/ `anger`（怒り）/ `sad`（悲しみ）/ `kind`（優しさ）/ `tease`（からかい）/ `anxiety`（不安）/ `tension`（緊張）/ `surprise`（驚き）/ `tired`（疲れ・ため息）/ `whisper`（囁き）/ `giggle`（忍び笑い）/ `fear`（恐怖）/ `sleepy`（眠気）/ `resolve`（決意・強調）

| ID | 絵文字 | ID | 絵文字 |
| --- | --- | --- | --- |
| `panting` | 🥵 | `calling` | 📢 |
| `sleep_talking` | 😴 | `fast` | ⏩ |
| `telephone` | 📞 | `slow` | 🐢 |
| `pained` | 😖 | `worried` | 😟 |
| `shy` | 🫣 | `exasperated` | 🙄 |
| `cheerful` | 😊 | `confident` | 😎 |
| `pleading` | 🙏 | `drunken` | 🥴 |
| `humming` | 🎵 | `relieved` | 😌 |
| `questioning` | 🤔 | `strong` | 💪 |
| `narration` | 📖 | | |

文中の特定位置に非言語音を入れる場合は、`😮‍💨 ⏸️ 🤭 🌬️ 😮 💋 🥤 🤧 👌 👃` を `tts_text` の該当位置へ挿入する。Unicodeの結合文字・異体字セレクタを保持する。  
`👅`（異音）、`🤐`（台詞に合わない声）、`🥱`（再現性不足）、`😒`（反復時の異音）はAIの自動選択から除外する。

#### 発話長の目安

Irodori-TTSの運用では**20〜80文字程度**を基本的な推奨範囲とする。15文字未満は不安定性に注意し、10文字未満の単独生成は可能な限り避け、80文字超は分割を検討する。原文・話者・意味・演出の境界を優先し、自然な短文統合だけを行う。水増しは禁止。

## 3. 読みと間の解釈

### 3.1 読み上げる文字列の解決
1. 原文にある作者ルビ、および `tts_text` 内の明示ルビ（`｜親文字《読み》`）は必ずその読みへ展開される。
2. `koebuta_added_ruby` にある追加ルビは、`selection: "kana"` なら指定の読みへ展開し、`selection: "surface"` なら元表記を維持し、`selection: "auto"` ならCLIのスコア判定（`auto_select`：テキストエンコーダ特徴量の類似度スコア `cos_cond` が閾値以下の候補を仮名化）に従って展開または元表記維持が選択される。
3. 青空文庫の既知の組版注記（`［＃改ページ］`、`［＃…字下げ］`、`［＃「…」は中見出し］`、`［＃「…」に傍点］` 等）は原文 `text` に保持され、音声合成入力からは自動的に除かれる。

### 3.2 発話後の間（休止）
- 発話に `pause_after_ms`（0〜10000の整数、0も明示指定）があればそれを最優先する。
- 未指定の場合、直後に区切り（`segment_type: "separator"`）があり `pause_after_ms` が指定されていればその最大値、それもなければ生成設定JSONの共通 `pause`（秒、既定0.28秒）を発話間に適用する。
- 休止は合算しない。生の改行や `blank_lines_after` から休止時間を自動推定しないため、必要な間は `pause_after_ms` に明示する。

## 4. 読み込み時の許容と問題の扱い

標準出力に必要な項目が欠けていても、エディタ等で編集用に読み込む際は可能な範囲で保持・通知する。ただしCLIでの音声生成時は、必須項目の欠落、未登録の `speaker_id`、ルビ範囲の不整合・衝突などがある場合は生成前にエラーとして停止し、該当箇所の発話IDと理由を表示する。

## 5. 原文の保全と検証

### 原文保持の限定的な例外
シナリオ作成時、ユーザーが明示的に許可した場合に限り、タイトル・著者名・章題・節題などの見出し類を、短文生成の不安定性回避や自然な導入のために必要最小限の文章へ改変し、変更後を `text` へ記録できる（既定は改変しない）。本文や台詞には適用せず、事実を創作せず、許可範囲外の順序・内容は保持する。

`source` を含める場合は改変前の入力原稿全文をそのまま保持する。CLIやエディタの原文照合は最初の不一致箇所を警告として通知するため、許可済み見出し改変か意図しない本文脱落かを人が確認する。警告を隠すために `source` を書き換えてはならない。

見出し類を含む短文の結合は、連続する原稿範囲の文字・空白・改行・順序をそのまま一つの `text` へ保持する場合（例：`"春の灯\n架空花子\n第一章"`）、改変許可を必要としない。

## 6. 用語の統一

画面・説明文・LLM用依頼文で用いる日本語は次に統一する。

| JSON内部キー・技術用語 | 表示する日本語 |
|---|---|
| `source` | 原稿全文 |
| `speakers` / `speaker_id` | 話者一覧 / 話者ID |
| `segments` / segment | 台本項目 / 発話（読み上げる項目） |
| `text` | 原文 |
| `tts_text` | 読み上げ文 |
| `koebuta_added_ruby` | 追加ルビ |
| `notes` | 編集指示 |
| `bio` | 人物像 |
| `voice_caption` | 声の特徴 |
| 話者の `acting_description` | 普段の話し方 |
| 発話の `acting_description` | 発話ごとの演技指示 |
| `emotion` | 感情 |
| `pause_after_ms` | 発話後の間 |
| `segment_type: "separator"` | 区切り（読み上げない） |
| 参照WAV | 参照音声 |

## 7. エディタ編集履歴の任意拡張

発話の `koebuta_edit` はエディタ（Scenario Inspector）での編集履歴を示す任意オブジェクトであり、音声生成の内容には影響しない。

```json
{"koebuta_edit":{"actions":["manual_split"],"needs_review":true,"fallback":false}}
```
